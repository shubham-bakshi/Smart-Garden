
Project Brief: DIY Multi-Node Smart Plant Monitoring System


1. Project Goal & Target Environment

• Objective: Build a multi-node plant monitoring system where several low-cost wireless sensor sticks (nodes) deployed across individual pots transmit real-time telemetry back to a single central gateway (hub), which then forwards the data to a smartphone.
• Tracked Metrics: Soil Moisture, Ambient Sunlight Level (Lux/Intensity), and Temperature.
• Deployment Context: A south-facing balcony in Bengaluru, India. The location receives direct sunlight during winter months and indirect sunlight during the rest of the year.

2. The Core Problem: Why Commercial Options Were Rejected

• The Import/Markup Problem: Off-the-shelf multi-node consumer systems (like Ecowitt GW hubs + WH51/WH52 nodes or Tuya Zigbee systems) are completely imported into India. Due to high customs duties, international freight, and low local volume, individual pre-built nodes cost anywhere from ₹2,500 to ₹6,000+ each, making scaling expensive.
• The All-in-One DIY Problem: Integrated developer options like the LILYGO T-Higrow ESP32 board (approx. ₹1,300–₹1,600 bare) also become prohibitively expensive once scaled. When adding separate waterproof enclosures, 18650 lithium batteries, and sensory add-ons to every single plant, the per-node cost defeats the budget-saving objective.

3. Approved Technical Architectures (Target Per-Node Budget: ₹250–₹400)

To bypass commercial markups and high Wi-Fi battery drain, the system design separates the "brains/connectivity" from the "sensor nodes" using low-power wireless frequencies instead of direct Wi-Fi.

Configuration A: Sub-GHz 433MHz Radio Frequency (RF)

• Central Hub Components (~₹500): A single wall-powered ESP8266 or ESP32 microcontroller paired with a 433MHz Superheterodyne Receiver module. The hub listens to radio packets and uploads them to the cloud/phone app via home Wi-Fi.
• Wireless Node Components (~₹250–₹350 per plant):
	• MCU: An ultra-low-power microchip like an ATTiny85 or Arduino Pro Mini (3.2V).
	• Radio: A cheap FS1000A 433MHz Transmitter module to beam short bursts of data.
	• Sensors: A mass-produced Capacitive Soil Moisture Sensor v1.2 (anti-corrosion coated, approx. ₹80) paired with a simple LDR (Light Dependent Resistor) for sunlight tracking.
• Pros: Deep walls penetration, incredible battery life (nodes can deep-sleep for hours), and the lowest possible scaling cost.

Configuration B: Bluetooth Low Energy (BLE) Beacon Mesh

• Central Hub Components (~₹350): A single ESP32 development board using its integrated Bluetooth radio to continuously scan for raw BLE advertisement packets, parse them, and forward them over Wi-Fi.
• Wireless Node Components (~₹400 per plant):
	• MCU & Wireless: A generic, compact nRF51822 or ESP32-C3 mini board configured to broadcast in BLE beacon mode without establishing formal connections.
	• Sensors: Standard Capacitive Moisture Sensor v1.2 and an LDR photodiode.
• Pros: No external radio module wiring/soldering required on the node; runs for months on cheap coin-cell batteries.

4. Hard Constraints for Implementation

• Component Sourcing: All parts must be common, generic electronics components easily sourced from domestic Indian hobbyist sites (e.g., Robu.in, Probots, Quartz Components) to avoid retail markups.
• Sensor Type: Strictly capacitive soil moisture probes. Resistive soil probes (cheap metal forks) are entirely excluded due to rapid oxidation and corrosion in wet balcony soil.
• Enclosure Needs: Nodes must be housed in compact, highly weather-resistant cases to survive high balcony humidity and accidental water splashing.

5. Nutrient Sensing — Future Expansion

• NPK sensing was investigated as a possible future capability. Commercial NPK sensors exist, but current India prices are generally too high to place one on every low-cost plant node.
• Decision: Do not include NPK sensing in the V1 wireless node. Keep V1 focused on soil moisture, sunlight, and temperature.
• Potential V2 approach: use a single shared/portable NPK sensor for occasional measurements rather than one NPK sensor per plant.
• EC (electrical conductivity) should be investigated as a potentially cheaper and more useful first nutrient-related metric before committing to NPK hardware.

6. Current Product Direction

• Core architecture: multiple low-cost wireless plant sensor nodes → one home hub/gateway → smartphone app.
• Primary goal: reduce per-plant hardware cost while retaining useful plant-level telemetry.
• Current target node cost: ₹250–₹400.
• Candidate communications: 433 MHz RF and BLE beacon architecture.
• V1 metrics: soil moisture, sunlight/light intensity, temperature.
• V2 candidates: EC, pH, NPK, humidity, and richer plant-care intelligence.
• Key product hypothesis: the hub should make it economical to monitor many plants without requiring an expensive Wi-Fi radio in every pot.

7. Development Roadmap — Later Phases

Phase 1: Feasibility Prototype
• Build 2–3 sensor nodes using both candidate architectures: 433 MHz RF and BLE beacon.
• Measure real-world range across the Bengaluru south-facing balcony/home environment.
• Validate reliable transmission through walls and around balcony obstacles.
• Measure battery consumption and estimate practical node battery life.
• Calibrate the capacitive moisture sensor against actual soil moisture conditions.
• Validate sunlight/light readings against a reference light meter where possible.
• Validate temperature readings against a reference thermometer.
• Goal: prove that low-cost nodes can reliably collect useful data before optimizing hardware cost.

Phase 2: Hub + Multi-Node System
• Build a single always-powered ESP32-based hub/gateway.
• Register multiple sensor nodes with unique IDs.
• Receive, decode, timestamp, and store readings from every node.
• Forward readings to a smartphone/local dashboard over Wi-Fi.
• Handle missing packets, low battery, duplicate packets, and node reconnect/restart scenarios.
• Target initial scale: 5–10 nodes per hub.
• Goal: demonstrate that one hub can reliably manage a practical indoor/balcony plant collection.

Phase 3: Cost-Optimized Hardware Prototype
• Reduce the node BOM toward the ₹250–₹400 target.
• Replace development boards with smaller/cheaper MCUs where practical.
• Optimize sensor power switching so moisture/light measurements do not continuously consume battery.
• Select the lowest-cost reliable radio architecture based on Phase 1 results.
• Design a compact custom PCB rather than relying on development boards.
• Design a weather-resistant enclosure suitable for balcony use.
• Compare coin-cell, AA/AAA, and rechargeable battery options.
• Goal: achieve repeatable low-cost nodes without sacrificing measurement reliability.

Phase 4: Plant Management App — V1
• Create a plant inventory: plant name/species, pot, location, and sensor ID.
• Display live and historical moisture, light, and temperature readings.
• Show each plant's current condition and recent trends.
• Record manual watering, fertilizing, repotting, and other care events.
• Generate simple watering/check recommendations from sensor readings plus plant-specific thresholds.
• Provide alerts for very dry soil, excessive moisture, abnormal temperature, or unusually low light.
• Allow users to see all plants from a single home dashboard.
• Goal: move from raw sensor data to a useful plant-management experience.

Phase 5: Intelligent Plant-Care Engine
• Build plant-specific moisture ranges rather than using one universal threshold.
• Incorporate plant species, pot size, soil type, light exposure, temperature, humidity, season, and watering history.
• Learn the normal drying pattern of each individual plant.
• Predict when a plant is likely to cross its watering threshold.
• Detect unusual behavior, such as soil staying wet much longer than normal.
• Distinguish between "check the plant" and "water the plant" rather than blindly issuing reminders.
• Explore weather and local environmental data for outdoor/balcony plants.
• Goal: make the system increasingly personalized instead of functioning as a simple reminder app.

Phase 6: Advanced Sensors / Nutrient Intelligence
• Investigate EC as the first lower-cost nutrient-related measurement.
• Evaluate pH sensing for usefulness, calibration complexity, and long-term maintenance.
• Test whether one shared/portable NPK sensor can provide useful periodic measurements.
• Avoid placing expensive NPK hardware on every plant unless the economics change significantly.
• Explore room humidity as a hub-level environmental metric rather than duplicating expensive sensors on every node.
• Consider additional measurements only when they lead to actionable plant-care recommendations.
• Goal: expand beyond moisture without destroying the low-cost multi-node architecture.

Phase 7: Productization
• Freeze the radio architecture based on reliability, cost, battery life, and regulatory considerations.
• Create a production-ready sensor PCB and hub PCB.
• Improve waterproofing, mechanical durability, battery access, and sensor-probe replacement.
• Add OTA firmware updates for the hub and, where practical, the sensor nodes.
• Establish manufacturing/test procedures for sensor calibration and node pairing.
• Develop a simple onboarding process: power hub → add sensor → assign sensor to plant → start monitoring.
• Define target retail pricing and starter-kit configurations.
• Goal: turn the prototype into a reliable consumer product rather than a hobbyist kit.

Phase 8: Pilot / Market Validation
• Deploy the system with a small group of real users with different numbers and types of plants.
• Measure installation difficulty, sensor reliability, battery life, false alerts, and user engagement.
• Identify which measurements users actually value.
• Test willingness to pay for hardware and any optional app subscription.
• Compare the product against existing plant-care apps and imported sensor systems.
• Validate whether the main value proposition is cost, automation, plant intelligence, or a combination of these.
• Goal: prove product-market fit before committing to larger-scale manufacturing.

Phase 9: Future Automation
• Investigate automatic watering using the same hub and plant-specific moisture thresholds.
• Add controllable pumps/valves as optional accessories rather than making them mandatory.
• Support rules such as: "water only when moisture is below threshold and the tank has sufficient water."
• Add safety features to prevent overwatering, leaks, or pump failures.
• Goal: progress from monitoring → recommendations → optional closed-loop plant care.

8. Key Product Principles

• Keep the expensive intelligence/connectivity centralized in the hub wherever possible.
• Keep individual plant nodes simple, low-power, and replaceable.
• Prefer measurements that lead to an actionable decision over collecting data for its own sake.
• Do not require one expensive sensor per plant if environmental inference or shared sensors can provide sufficient accuracy.
• Avoid locking the V1 architecture to expensive proprietary hardware or cloud services.
• Prioritize components that are readily available in India.
• Treat sensor calibration, battery life, waterproofing, and radio reliability as first-class product requirements.
